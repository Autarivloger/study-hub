# Final retrospective — fill in your own evidence

## What I built

Name the user problem, the version-one boundary and which acceptance scenarios
you personally demonstrated. Distinguish reading a lesson, reproducing its result,
making an independent implementation and operating a real deployed service.

## Decisions and evidence

Explain SQLite versus a separate database server, the API/domain/storage split,
the version comparison for stale edits, and why the browser uses textContent.
Include one failure you reproduced, its regression test and the correction.
Record measurements with workload/scope; do not invent a universal speed claim.

## Honest release record

Mark completed: local tests, real HTTP restart, restore, browser workflow, installed
wheel. Record which you actually ran. Mark a public/second-device deployment only
after performing it yourself and keeping observable evidence. A recipe is not a run.

## Next six months (adjust to your time and evidence)

1. Independently rebuild one vertical slice; test SQL and API contracts without a template.
2. Extend one feature with a migration plan, a backup and backward-compatibility tests.
3. Learn multi-user identity/authorization and add it to a separate practice branch.
4. Operate a deliberately private deployed instance; rehearse outage, restore and token rotation.
5. Contribute one focused upstream fix or documentation improvement with an actual review.
6. Refactor based on measured usage and write a portfolio case study with real limits.

Use additional weeks whenever needed. Completion is demonstrated understanding,
not merely reaching a calendar date or pressing the final lesson's checkbox.
